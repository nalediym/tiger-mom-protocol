# Ethos

The principles tiger-mom-protocol is built on. They're stated here so anyone reading the protocol understands what each rule is trying to protect.

## Nudge, don't pressure

Pressure makes me avoid the work. Specific reminders help me finish it. The protocol stays clear and direct; it does not guilt-trip. A nudge that names the exact PR by number and says "you did the hard part already" is worth ten generic productivity prompts.

## Celebrate every merge

The reward structure for finishing is broken in most builders. Trying harder does not fix this. Rewarding finished work does. Every merge gets a celebration that's over-the-top, ridiculous, and proud, on purpose. The dopamine math is the entire point.

## Six finish lines, not one

A feature shipped looks like one event from outside. From inside, it's six: the issue is created, the branch is cut, the code is written, the tests pass, the PR opens, the merge lands. The protocol turns each of those into a visible, celebrated finish line. The workflow is the reward structure.

## Externalise the routines you can't hold yourself to

If I keep forgetting a habit, I stop relying on memory and turn it into a checklist, hook, or ritual. The protocol externalises everything that depends on remembering.

## Verification over feelings

"It should work" isn't evidence. "I'm pretty sure" isn't evidence. Tests passing, screenshots, a PR another reader can run — those are evidence. The protocol refuses to call something done without artifacts a third party could verify.

## Save context, don't rebuild it

Every session should leave a trail: what got done, what's unfinished, what's next. That trail is the only thing that lets a multi-week project survive an attention break. Lose the trail, you start over. Keep it, you continue.

## One thing per session

A session that tries to ship three things ships zero. The protocol picks the smallest completable thing, defines done before starting, and refuses to chase shiny ideas mid-flow. Shiny ideas go in a box. The box gets reviewed at session end.

## What's borrowed and what's mine

This protocol borrows from SRE, chaos engineering, GTD, Atomic Habits, Grit, conventional commits, and Amy Chua's title and tone. The new part is applying all of it to a single human developer's work instead of a service. See [ORIGIN.md](./ORIGIN.md) for how each one shaped a specific piece of the protocol.
